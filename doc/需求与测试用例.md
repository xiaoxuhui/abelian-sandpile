## 一、产品目标与用户流程

让用户通过投沙与连锁崩塌观察简单局部规则产生的复杂图案，并通过有限操作的关卡理解传播与边界耗散。提供中文界面、离线运行、鼠标/键盘/触摸操作。

自由探索流程：选择棋盘 → 点击或按键投沙 → 单步观察或播放崩塌 → 查看稳定图案及统计 → 保存实验。

挑战流程（拟议）：选择关卡 → 阅读初态、目标、允许投沙位置及次数预算 → 每次投下一粒 → 等待本次雪崩稳定 → 比较目标 → 成功、继续尝试或重置。

## 二、数学规则与术语

以下作为标准二维方格沙堆模型的需求基线。依据与适用范围见[玩法调研](玩法调研.md)。

1. 棋盘每格保存非负整数粒数，上下左右是四个邻接方向，不含对角线。
2. 粒数达到或超过 4 时，该格不稳定；一次合法崩塌使自身减少 4，四个方向各获得 1。
3. 拟议首版使用有限矩形棋盘和开放耗散边界：发往棋盘外的沙计入流失量，边格阈值仍为 4。禁止把角格阈值改成 2、边格改成 3。
4. 稳定指所有格粒数均小于 4。暂停仅停止推进，不代表已稳定。
5. 在同一含可达汇点的有限图、同一初态与相同投沙输入下，合法崩塌顺序不改变最终稳定配置；中间动画允许不同。这才是此处“阿贝尔”的含义。
6. 拟议统计口径：一次基础崩塌计 1；批量处理某格 k 次必须计 k。一次雪崩指稳定棋盘接受一次投沙操作后直到重新稳定的完整过程；其大小为累计基础崩塌次数。自由模式一次批量投沙可作为一个输入事件，挑战模式始终每次一粒。
7. 质量账本：当前棋盘总量 + 累计流失量 = 本局初始总量 + 累计投入量。清空、重置、换预设开始新账本，不计作物理耗散。
8. 动画速度、暂停、单步和计算批次不得改变稳定终态；连续投沙时只能在停止输入后讨论整体稳定。

不把这一离散模型描述为真实沙子的精确物理模拟。首版不承诺用户任意实验都呈现幂律，也不把单次中心堆沙图案称为沙堆群单位元。

## 三、自由探索模式（拟议首版）

### 3.1 棋盘与投沙

- 提供空棋盘、中心堆沙、满 3 后加一粒三类预设；所有预设以数据描述并经过测试。
- 建议默认 65×65，提供 33×33、65×65、129×129 三档。尺寸与上限是工程候选值，性能验证后定稿。
- 单击选中格并投沙；提供每次 1、10、100、1000 粒及合法整数输入。先完成离散点击，拖动连续投沙延后，避免触摸滚动歧义。
- 运行中允许离散投沙，操作进入有序输入队列；页面忙碌时清楚显示排队状态，不静默丢操作。
- 改尺寸、载入预设、清空均停止旧任务并开始新实验；已有内容需明确确认，取消保留现场。

### 3.2 演化与显示

- 运行/暂停、单步、稳定化及速度控制；“稳定化”仍分帧计算且可以中止，不冻结页面。
- 单步定义为一轮同步波：对轮开始时所有不稳定格，各做一次基础崩塌，再统一应用邻格增量。新不稳定格留到下一轮。
- 显示 0/1/2/3 粒图例、不稳定格标记、选中格坐标及粒数；小棋盘可显示数字，颜色不是唯一信息通道。
- 展示当前总量、累计投入、累计流失、累计崩塌、当前/最近一次雪崩大小、运行与稳定状态。
- 首版范围内不提供无限棋盘、环绕边界、八邻接、可变阈值或 GPU 加速。

## 四、挑战关卡（拟议规则，未实现）

### 4.1 胜负与操作

- 使用相同的四邻接、阈值 4 和开放边界，不为关卡另造物理规则。
- 每关给定尺寸、稳定初态、稳定目标、允许投沙位置、最大投沙次数和说明。每次合法投沙恰好一粒、消耗一步。
- 仅稳定态允许下一次投沙；雪崩期间可暂停或查看，不允许更改棋盘和额外叠加输入。
- 胜利条件：重新稳定后，全棋盘每格与目标粒数完全相等。没有“包含目标即可”或仅比较总量的捷径。
- 次数耗尽且稳定后不匹配显示“本次未达成”；最后一次投沙先判断匹配，再判断失败。
- 初态已经等于目标时允许零步完成；正式关卡原则上避免此类无操作关。非法位置、越界或忙碌点击不扣次数。
- 提供重置与关卡内撤销；撤销恢复上一个稳定快照、步数和统计。运行中的重置取消旧计算任务，旧结果不能写回新局。
- 首版只记录完成状态与个人最好步数，暂不设星级、排行榜、计时惩罚或奖励货币。

### 4.2 关卡路线

| 阶段 | 教学目标 | 设计方向 | 验证要求 |
| --- | --- | --- | --- |
| 入门 | 理解 3→4 崩塌 | 中心一粒触发十字 | 完整模拟得到目标 |
| 传播 | 邻格触发下一次崩塌 | 两段链、分叉 | 验证基础崩塌次数与终态 |
| 边界 | 边角流失 | 选择内点或边点投沙 | 粒数账本正确 |
| 选择 | 不同落点的不同结果 | 多个候选位置、有限预算 | 穷举证明可解 |
| 组合 | 加法顺序与终态 | 多次投沙达到精确图案 | 验证不同合法顺序及最优性声明 |

初始调研未承诺关卡数量；后续迭代建议将 v0.1.0 目标细化为 6 个经过验证的教学关，主题见版本迭代规划。未通过可解性和对应最优性门槛的候选不能当作正式关卡。示例数据 `data/challenges/example.json` 仅用于固定草案格式，不作为可玩的已验证关卡。

### 4.3 可重复关卡验证

实施时必须新增 `node scripts/verify-levels.mjs`：遍历允许投沙位置，按步数逐层搜索；每个动作后按规则稳定化，记录最早命中目标的深度。可按“棋盘稳定态+已用步数”去重，不得只凭参考解声称最少步数。

若搜索超过明确预算，报告“最优性未证明”，不得静默降低断言或给出最少步数/星级门槛。关卡编号与版本保持稳定，关卡修改需评估存档与最好步数的有效性。

## 五、保存、导入与兼容性（拟议）

- 本地键固定前缀 `abelian-sandpile.`，候选键为 `abelian-sandpile.experiment.v1`、`abelian-sandpile.progress.v1`、`abelian-sandpile.settings.v1`。
- 页面退出或后台化时保存最近完整状态；恢复后默认暂停，不自动继续投沙或无限计算。
- 导出版本化 JSON；导入先完整校验 gameId、schemaVersion、规则、尺寸、数组长度、非负安全整数、总量及统计一致性，再一次替换。错误文件不修改现有数据。
- 自由模式可保存不稳定棋盘，但需保留物理账本；挑战进度保存稳定快照和已用步数。运行任务队列不作为长期存档对象。
- 存储不可用/配额满时保留当前内存数据并提示，允许手动导出；不调用 localStorage.clear()/sessionStorage.clear()。
- 单独网页和大厅 URL 的 origin 不同，迁移依靠导入导出；不承诺自动读取旧浏览器或其它 APK 数据。
- 原生导出桥尚未为第五个游戏注册；大厅端需先定桥协议并实测文件落盘，不能直接复制其它游戏的桥名称。

## 六、游戏大厅与开源需求

- 自包含离线网页，页面资源采用相对路径；支持 `/assets/games/abelian-sandpile/index.html` 子路径，无 CDN、在线字体、运行时依赖下载或根路径假设。
- 新增来源必须锁定完整 40 位 Git SHA，资源白名单/字节数/SHA-256 可复核；大厅只读消费独立检出的来源。
- 大厅现有四个固定游戏限制必须由大厅项目另行修改并回归，本项目准备合约不等于已接入。
- 版本、存档合同与资源协议分开；未来动态协议尚未落定，不捏造宿主版本范围、签名、仓库 URL 或下载通道。
- 延续 EML 的 MIT 许可与贡献规范，保留 CHANGELOG、SECURITY、第三方来源说明、开发文档和测试记录。运行与骨架测试不需要外部依赖。
- 用户已补充授权创建远程和推送，本游戏源码现公开于 xiaoxuhui/abelian-sandpile；没有正式 Release。未来标签、Release 或独立 APK 属于后续授权范围。大厅 APK 不属于本窗口范围。

## 九、待定与延后

- 挑战胜利规则、撤销、预算及关卡数量仍是拟议方案，完整实现前收敛。
- 棋盘/粒数/导入大小/帧预算上限要实测后定稿，不将候选数值描述为性能保证。
- 正式图标、远端地址、独立 APK、大厅第五游戏支持和动态下载协议后续安排。
- 无无限世界、真实颗粒碰撞、多用户联机、排行榜或幂律拟合结论。
