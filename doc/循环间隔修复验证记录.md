# 循环间隔修复验证记录

日期：2026-10-09。范围：当前开发网页的输入约束修复，未发行；既有 v0.1.2 APK 不包含本改动。

## 原因与行为

需求及控制器均接受 100..5000ms 的任意整数，输入框却配置 step=100，浏览器把 137、250 等值标记为步长不匹配。改为 step=1，上下限和默认 500ms 保持原样。没有修改数学规则、循环调度、存档或大厅。

首次运行新增浏览器断言失败：137ms 的 checkValidity() 返回 false，见 [修复前输出](evidence/interval-fix/red-browser.txt)。随后实施修复，桌面原生校验接受 137ms，上下键 137→138→137，实际循环配置保持 137；320px 触摸输入 250ms，实际配置保持 250。99、5001、137.5 的原生校验及启动均拒绝，棋盘不变。
